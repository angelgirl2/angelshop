# Angel shop
- `lib/` برنامه Flutter | `android/` پروژه اندروید (Gradle آماده) | `worker/` سرور Cloudflare Worker + KV | `.github/workflows/` دیپلوی خودکار

## اجرا در VS Code
1. Flutter SDK + Android Studio (برای Android SDK و JDK 17) + افزونه‌های Flutter/Dart را نصب کنید؛ `flutter doctor`.
2. پوشه را در VS Code باز کنید: `flutter pub get`
3. در `.vscode/launch.json` آدرس Worker را بگذارید، گوشی/شبیه‌ساز را وصل کنید و F5.
   یا: `flutter run --dart-define=API_URL=https://...workers.dev`
4. APK: `flutter build apk --release --dart-define=API_URL=https://...workers.dev`
(بار اول، دانلود Gradle و وابستگی‌ها چند دقیقه طول می‌کشد. فایل gradlew را خود Flutter می‌سازد.)

## راه‌اندازی Worker و گیت‌هاب (یک‌باره)
1. کلودفلر → KV → Create (نام DB)؛ شناسه را در `worker/wrangler.toml` بگذارید.
2. API Token با قالب «Edit Cloudflare Workers» + Account ID.
3. GitHub → Settings → Secrets → Actions: `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`, `BOT_TOKEN`, `ADMIN_CHAT_ID`, `WEBHOOK_SECRET` (رشته تصادفی بلند), `WORKER_URL`
4. فایل محصولات را در `worker/products.json` بگذارید و Push کنید.

## از این به بعد
- Push به `worker/**`: دیپلوی Worker، رمزها، همگام‌سازی محصولات، وبهوک بله.
- Push به `lib/**` یا `android/**`: ساخت APK (Actions → Artifacts).
- قیمت/موجودی/توضیحات: از ربات بله (`/help`).

## امکانات تکمیلی پشتیبانی و فروش

### پاسخ‌گوی هوشمند
- Worker به binding رسمی Cloudflare Workers AI با نام `AI` متصل است.
- مدل پیش‌فرض: `@cf/google/gemma-4-26b-a4b-it`.
- دستیار اطلاعات محصول را از کاتالوگ فعلی Worker می‌خواند؛ قیمت و موجودی را حدس نمی‌زند.
- در بازه‌ای که برای اپراتور انسانی تعیین می‌کنی، پیام‌ها به تیکت ثبت می‌شوند و در ربات بله اعلان می‌گیری. خارج از بازه، پاسخ‌گوی هوشمند جواب می‌دهد.

### تنظیم ساعت پشتیبانی در ربات بله
تمام زمان‌ها به وقت تهران هستند و دستور ربات تاریخ شمسی می‌پذیرد:

```text
/support_schedule 1405/08/23 09:00 1405/08/23 18:00
/support_status
/support_off
/reply TKT-ID متن پاسخ
/close TKT-ID
```

`/support_schedule` یک بازه شروع و پایان مشخص می‌کند؛ برای بازه جدید، دستور را دوباره بفرست. `/support_off` پشتیبانی انسانی را خاموش می‌کند و پاسخ‌گویی هوشمند فعال می‌ماند.

### پنل مدیریت مخفی
- مسیر پنل: `/manage` روی دامنه Worker.
- برای تعیین رمز ورود، در گفت‌وگوی خصوصی ربات بله (از حساب ادمین) دستور زیر را بفرست:

```text
/admin_password YourStrongPassword12
```

- رمز باید حداقل ۱۲ کاراکتر باشد. سپس وارد `/manage` شو. لینک پنل داخل برنامه نمایش داده نمی‌شود؛ APIهای مدیریتی نیز بدون نشست مدیر قابل استفاده نیستند.
- امکانات کامل محصولات، دسته‌بندی، تصاویر، سفارش‌ها، تیکت‌ها، تنظیمات AI و زمان‌بندی انسانی، تخفیف‌ها و رمز مدیر در پنل وب موجود است.

### کد تخفیف و فاکتور
- فقط کدهایی که مدیر در پنل می‌سازد پذیرفته می‌شوند.
- محاسبه تخفیف و مبلغ نهایی دوباره در Worker انجام می‌شود؛ مبلغ ارسالی از برنامه مبنای اعتماد نیست.
- پس از ثبت موفق سفارش، فاکتور با طراحی بنفش Angel Shop در برنامه ساخته و به شکل تصویر نمایش داده می‌شود.

### فایل‌های پیوست تیکت
تصویر، ویدئو و PDF در حال حاضر با سقف ۵ مگابایت برای هر فایل پذیرفته می‌شوند و در KV همان Worker ذخیره می‌شوند و پس از ۹۰ روز به‌صورت خودکار منقضی می‌شوند. برای آرشیو حجیم ویدئوها، در آینده بهتر است ذخیره‌سازی پیوست‌ها به R2 منتقل شود.

### نکته هزینه
اجرای مدل Workers AI مصرف محاسباتی Cloudflare دارد و ممکن است هزینه مصرف ایجاد کند؛ قبل از فعال‌کردن پاسخ‌گویی عمومی، سقف مصرف و صورتحساب حساب Cloudflare را بررسی کن.


## مدیریت کامل کاتالوگ با ربات بله

`worker/products.json` کاتالوگ پایه و ترتیب اولیه محصولات را نگه می‌دارد. قیمت‌ها و مشخصات در زمان اجرا از API خوانده می‌شوند: مقدار پایه از JSON و تغییرات مدیریتی از KV با اولویت بالاتر اعمال می‌شود. بنابراین قیمت‌ها در اپ هاردکد نیستند و با دستورهای ربات بله بدون انتشار نسخه جدید برنامه تغییر می‌کنند.

دستورهای ربات: `/list`، `/info ID`، `/price ID[,ID] PRICE`، `/stock ID NUMBER|on|off`، `/name ID NAME`، `/cat ID CATEGORY`، `/desc ID` همراه متن چندخطی در همان پیام، `/img ID URL`، `/active ID on|off`، `/categories`، `/categoryrename OLD | NEW`، `/addproduct` همراه فیلدهای name/price/category/stock/description و `/deleteproduct ID` برای غیرفعال‌سازی محصول.

محصولات افزوده‌شده در KV با کلید `products_extra` ذخیره می‌شوند و با انتشار کد یا تغییر JSON حذف نمی‌شوند. دسته‌ها از دسته‌بندی محصولات استخراج می‌شوند؛ با افزودن محصول یا اجرای `/cat` می‌توان دسته تازه ایجاد کرد.

### ترتیب عکس‌های محلی

تصاویر در `assets/product/` هستند. رکورد اول `worker/products.json` از `01.png`، رکورد دوم از `02.png` و ... استفاده می‌کند. ترتیب با فیلد `catalog_index` از Worker می‌آید؛ غیرفعال‌کردن محصول باعث جابه‌جایی عکس سایر محصولات نمی‌شود. محصولات تازه در انتهای کاتالوگ قرار می‌گیرند؛ برای محصول ۳۵ فایل `35.png` و برای محصول بعدی `36.png` اضافه کنید. نام و فرمت PNG را حفظ کنید. برای محصولات بدون تصویر اختصاصی از فایل محلی استفاده می‌شود؛ تصویر بارگذاری‌شده در پنل از Worker دریافت می‌شود.

تعداد رکوردهای فایل JSON در نسخه فعلی ۳۴ است؛ محصول جدید از شناسه بعدی ساخته می‌شود و در انتهای فهرست قرار می‌گیرد.

## نسخه تکمیل‌شده پنل مدیریت و همگام‌سازی زنده

پنل وب مدیریت روی مسیر `/manage` اکنون از همان داده‌های مشترک ربات بله استفاده می‌کند و شامل این بخش‌هاست:

- **محصولات:** افزودن و ویرایش نام، قیمت، دسته، موجودی، توضیحات کامل، فعال/غیرفعال‌کردن، بازگردانی تغییرات به مقدار پایه و غیرفعال‌سازی بدون حذف سوابق.
- **تصاویر محصولات:** بارگذاری JPG/PNG/WebP تا ۱.۵ مگابایت از پنل؛ تصویر در KV ذخیره و از مسیر عمومی `/product-images/ID` در اپ نمایش داده می‌شود. اگر تصویری برای محصول بارگذاری نشده باشد، اپ از تصویر محلی `assets/product/` استفاده می‌کند.
- **دسته‌بندی‌ها:** ایجاد دسته جدید و تغییر نام دسته برای همه محصولات مرتبط.
- **سفارش‌ها:** مشاهده سفارش‌های ثبت‌شده و تأیید یا رد سفارش‌های در انتظار؛ وضعیت از همان مخزن داده مشترک خوانده می‌شود.
- **تیکت‌ها:** مشاهده گفتگو و فایل‌های پیوست، پاسخ مدیر و بستن تیکت.
- **پشتیبانی هوشمند:** فعال/غیرفعال‌کردن AI خارج از ساعات انسانی، دستورالعمل اختصاصی، میزان خلاقیت و سقف توکن پاسخ.
- **زمان‌بندی انسانی:** تعیین تاریخ شمسی و ساعت شروع/پایان به وقت تهران؛ همان تنظیم در ربات بله نیز اعمال می‌شود.
- **تخفیف‌ها و رمز پنل:** مدیریت کدهای تخفیف و تغییر رمز ورود پنل.

### همگام‌سازی زنده

برای اعلان تغییرات، Durable Object با نام `LiveHub` به Worker افزوده شده است. پنل و اپ از WebSocket اعلان می‌گیرند؛ پس از تغییر محصول از پنل یا ربات، داده محصول به کلاینت‌های متصل ارسال می‌شود و لازم نیست APK دوباره ساخته شود. همگام‌سازی دوره‌ای نیز به‌عنوان مسیر پشتیبان فعال است. برای این قابلیت، هنگام انتشار Worker باید migration مربوط به `LiveHub` اجرا شود؛ دستور `wrangler deploy` در Workflow این کار را با تنظیمات موجود انجام می‌دهد.

نکته: اعلان WebSocket زنده است؛ اما دریافت تصویر جدید از KV ممکن است تحت تأثیر انتشار منطقه‌ای KV قرار بگیرد. برای کاتالوگ‌های بسیار بزرگ یا تصاویر پرتعداد، انتقال تصاویر به Cloudflare R2 انتخاب مقیاس‌پذیرتری است.

### انتشار نسخه جدید

1. کل محتوای این سورس را در شاخه `production-ready` مخزن قرار بده.
2. GitHub Actions با Workflow به نام `Angel Shop Production` را اجرا کن.
3. پس از موفقیت Deploy، پنل را از `https://آدرس-Worker/manage` باز کن.
4. اگر هنوز رمز پنل تعیین نشده، یک بار در ربات بله دستور `/admin_password` با رمز حداقل ۱۲ نویسه را اجرا کن؛ پس از ورود، رمز را از بخش «هوش مصنوعی و ساعات پشتیبانی» هم می‌توان تغییر داد.

این بسته به‌صورت سورس آماده شده است؛ تا زمان اجرای موفق GitHub Actions، تغییرات روی Worker آنلاین منتشرشده محسوب نمی‌شوند.

## مدیریت مسئول پاسخ‌گویی هر تیکت

در پنل `/manage` و بخش «تیکت‌ها»، برای هر تیکت می‌توان مسئول پاسخ‌گویی را جداگانه تعیین کرد:

- `خودکار طبق ساعات پشتیبانی`: از برنامه زمانی سراسری استفاده می‌کند؛ در ساعات انسانی مدیر و خارج از آن آنجی (در صورت فعال بودن AI).
- `فقط مدیر`: پیام‌های بعدی مشتری برای مدیر ارسال می‌شود و آنجی خودکار پاسخ نمی‌دهد.
- `آنجی`: آنجی مستقل از برنامه ساعات انسانی پاسخ می‌دهد. هنگام واگذاری به آنجی، اگر آخرین پیام بی‌پاسخ از مشتری باشد، آنجی همان لحظه پاسخ می‌دهد.

ارسال پاسخ دستی از پنل یا دستور `/reply` در ربات بله، کنترل همان تیکت را به مدیر واگذار می‌کند. این انتخاب فقط روی همان تیکت اثر دارد و تنظیم سایر گفتگوها را تغییر نمی‌دهد. حالت انتخاب‌شده در KV ذخیره می‌شود و پس از Deploy باقی می‌ماند.
